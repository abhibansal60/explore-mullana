## Defect and root cause

After the service worker installs, `/` and `/helplines/` are cached. Navigate
to an uncached URL such as `/around/` or `/?q=chai` while its network request
stays pending. The four-second timer checks only that exact URL, finds no
cached response, and waits on the same stalled network request. The saved
homepage is never used until the network rejects. The directory can therefore
remain unavailable on a connection that stalls without reporting offline.

The timer now reuses the existing failure fallback: exact cached page, then
saved homepage. If neither exists it still waits for the network. A prompt
network response still wins. Cache version advances from v4 to v5, as required
by repo guidance for worker changes.

## Limits

This preserves the existing fallback behavior: an uncached guide URL can show
the saved homepage, rather than the unavailable guide. It does not make all
guides available offline. A first visit without any saved response still needs
the network. No live deployment, real phone, production data, private Sheet,
or physical mobile-network check was used. Chromium runs against Astro preview,
so Cloudflare response headers are not part of this check. The fix remains
subject to CI and review; no merge or deploy is authorized.
